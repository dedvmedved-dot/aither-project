# K3s vs K8s — обоснование выбора для Aither Platform

## Исходные данные

- 2× YADRO VEGMAN S320 (56c/112t, 768 GB RAM, 2× Quadro RTX 6000)
- Развёртывание на RED OS 8.0 (ядро 6.12, Docker 28.1)
- Нагрузка: vLLM (GPU-инференс), Portal BFF, PostgreSQL, Redis, мониторинг
- Production-эксплуатация

## Сравнение

| Критерий | K3s | K8s (kubeadm) | Вердикт |
|---|---|---|---|
| **GPU-поддержка** | NVIDIA GPU Operator ✓ (ограничения по node labeling) | NVIDIA GPU Operator ✓ (полная) | K3s — достаточно |
| **Установка** | 1 бинарник, 1 команда | kubeadm + etcd + control-plane | **K3s проще** |
| **etcd** | Встроенный (или внешний) | Отдельный обязательный | K3s экономнее по RAM |
| **Память control-plane** | ~512 MB | ~2 GB | K3s экономит 1.5 GB |
| **Развитие до multi-node** | Полноценная поддержка | Полноценная поддержка | Равно |
| **Helm, CRD, Operators** | Полная совместимость | Полная совместимость | Равно |
| **Обновления** | Канал стабильных версий | Требует ручного планирования | K3s проще |
| **High Availability** | Embedded etcd + 3 masters | Внешний etcd-кластер | K8s чуть надёжнее |
| **Сообщество / документация** | Rancher/SUSE, быстро растёт | Огромное | K8s чуть лучше |
| **RED OS совместимость** | ✅ (бинарник, системные требования низкие) | ✅ (но сложнее с зависимостями) | K3s проще |

## Рекомендация: **K3s**

Обоснование:

1. **Экономия RAM.** Control-plane K3s потребляет ~512 MB против ~2 GB у kubeadm. На каждом сервере с 768 GB разница незаметна, но **при 2 серверах с GPU vLLM важен каждый гигабайт для кэша моделей**.

2. **Простота.** Один бинарник, одна команда установки. Критично для RED OS, где пакеты могут отставать.

3. **GPU-оператор.** NVIDIA GPU Operator сертифицирован для K3s. Работает без отличий от K8s.

4. **NVLink.** K3s корректно пробрасывает NVLink-топологию через device plugin — vLLM увидит оба GPU как связанные.

5. **Развитие.** При росте до 3+ серверов K3s добавляет мастер-ноды так же, как kubeadm.

## Ситуации, когда стоит перейти на K8s

| Ситуация | Порог |
|---|---|
| Multi-tenant SaaS (десятки организаций с изоляцией) | >20 организаций |
| Жёсткие требования безопасности (OPA/Gatekeeper, Istio mTLS) | Compliance |
| Кластер >10 узлов с разнородными нагрузками | >10 nodes |
| Сертификация Kubernetes (CKA/CKAD) обязательна для команды | HR-требование |

## Итог

**K3s** — оптимальный выбор для Aither. При росте миграция на K8s тривиальна (Helm-чарты не меняются, API идентичен).
