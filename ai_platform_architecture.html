Execution plane на Kubernetes

Pool 1
CPU inference
Embeddings, компактные LLM, batch-обработка, экономичные маршруты, высокая плотность размещения.
Pool 2
GPU inference
Qwen/vision/OCR/speech, длинный контекст, latency-sensitive сервисы, дорогие, но производительные маршруты.
Pool 3
RAG data
Parsing, OCR, chunking, vector DB, retrieval, индексация знаний, доступ по ACL и traceability.
Pool 4
MLOps
Дообучение, evaluation, registry, controlled rollout, изолированный жизненный цикл моделей и датасетов.
Scheduler policy
Node affinity, taints/tolerations, resource quotas, priority classes, custom autoscaling по очередям и токенам/с.
Isolation
Раздельные service accounts, network policies, namespaces + выделенные node pools для чувствительных контуров.
Economics
Контроль утилизации GPU, лимиты холостого времени, перевод части нагрузки на CPU-only и асинхронные профили.

Control plane и алгоритм оптимизации

Что знает control plane
• Каталог моделей и их классов: compact, premium, vision, speech, embeddings
• Таблицы стоимости маршрутов: CPU-only, GPU-A100, RAG premium, async
• Таблицы относительной производительности и SLA-профилей
• Текущая загрузка: очереди, p95 latency, utilization, свободные слоты
• Policy flags: можно ли RAG, tool-use, vision, хранение trace
Как выбирается маршрут
1. Определяется тип запроса и ожидаемый объём токенов
2. Формируется список допустимых моделей и профилей исполнения
3. Для каждого маршрута оцениваются latency, cost и ожидаемая маржа
4. Отбрасываются маршруты, не проходящие SLA и policy constraints
5. Выбирается маршрут с максимальной маржой и приемлемым риском деградации
Цель алгоритма — использовать дорогой GPU только там, где он реально нужен для соблюдения SLA или качества, а всё остальное уводить на CPU-only, меньшие модели или асинхронный маршрут.

Security by design

Изоляция
Разделение inference, RAG и fine-tuning; отдельные node pools и сервисные учётные записи; отдельные policy profile для чувствительных контуров.
Защита входа
Prompt injection checks, jailbreak detection, классификация запроса, masking и DLP до передачи в модель.
Защита выхода
Output moderation, redaction, запрет утечки служебной информации, внутренних идентификаторов и чувствительных данных.
RAG security
Access-aware retrieval, ACL на документы, аудит retrieved chunks, контроль источников, защита от poisoning и traceability происхождения ответа.
MLOps security
Отдельный контур для датасетов и дообучения, model registry, evaluation gates, контролируемый выпуск fine-tuned моделей в production.

Дорожная карта развития

Этап 1
Inference
Единый API, CPU/GPU профили, модельный каталог, телеметрия, базовая безопасность, SLA.
Этап 2
Cost-aware routing
Маржинальная маршрутизация, приоритеты, fallback, профили премиум/базовый, оптимизация утилизации.
Этап 3
RAG
Ingestion, OCR, embeddings, retrieval, vector DB, policy-aware доступ к знаниям и цитируемость ответов.
Этап 4
Fine-tuning
Адаптация моделей под ИС, registry, evaluation, выпуск доменных моделей и controlled rollout.
Последовательность важна: сначала стабилизируется сервисный inference-контур и экономика, затем добавляется data plane для RAG, и только после этого — управляемый MLOps/fine-tuning.
