### 12. Observability (день 11)

```
Grafana → Prometheus → nvidia-dcgm-exporter (GPU-метрики)
                     → vLLM /metrics (throughput, KV cache)
                     → PostgreSQL (биллинг, пользователи)
                     → Gateway (latency, rate limits)
```

**Панели дашборда:**
- GPU: температура, utilisation, память, throttle
- Инференс: запросы/сек, токены/сек, KV cache hit rate
- Биллинг: объём списаний по моделям, балансы организаций
- Инфраструктура: latency по эндпоинтам, ошибки 4xx/5xx

### 13. ЮKassa боевой режим (день 12)

- Регистрация в ЮKassa → `shopId` + `secretKey`
- `YOOKASSA_SHOP_ID` + `YOOKASSA_SECRET` в `.env` на VPS2
- Тестовый платёж на 1 ₽
- Webhook-обработчик: проверка подписи, зачисление

### 14. AI Security Gateway (день 13)

Базовая версия (6 фильтров) уже работает. Расширенная:
- DLP: детекция номеров карт, паспортов, СНИЛС
- Jailbreak-детектор: adversarial prompts
- Rate limit per-user (не только per-org)
- Audit log: все заблокированные запросы

### 17. RAG (дни 15–16)

```
Документ → embedding (nomic-embed-text) → ChromaDB
Запрос → embedding → similarity search → контекст → промпт → модель
```

**Применение:** внутренняя документация Гринатома, техподдержка, поиск по базе знаний.

### 18. Fine-tuning (дни 17–18)

```
Датасет (JSONL) → LoRA-адаптер → слияние с базовой моделью → деплой в K8s
```

**Применение:** адаптация модели под доменную терминологию, стиль ответов.

### 19. Cost-aware routing (день 18)

Gateway анализирует запрос и выбирает модель:
- Короткий запрос → 14B (дешевле)
- Длинный/сложный → 32B (качественнее)
- Fallback: если 32B занята → 14B

### 21a. Тарифные планы (день 22–24)

Многоуровневая система подписок с разными лимитами и доступом к моделям.

```
Тариф «Free»       → 14B, до 100 запросов/день, общая очередь
Тариф «Standard»   → 14B + 32B, до 1000 запросов/день, приоритетная очередь
Тариф «VIP»        → всё + RAG, до 10K запросов/день, выделенные GPU-слоты
Тариф «Enterprise» → on-premise, кастомные модели, SLA, аудит
```

**Что нужно сделать:**
- Модель данных: `subscription_tiers` (лимиты RPM, модели, RAG, приоритет)
- Привязка `org → tier` с наследованием лимитов в Gateway
- Rate Limiter с разными окнами для разных тарифов
- UI в портале: карточки тарифов, сравнение, кнопка «Апгрейд»
- Интеграция с ЮKassa для платных тарифов (Standard/VIP)
- Автоматический даунгрейд при неоплате

**Фундамент уже есть:**

### Ключевое требование

Пакет должен позволять специалисту **без доступа в Интернет**:

1. Скопировать каталог на флеш-носитель
2. Перенести на целевую машину (Astra Linux)
3. Загрузить все офлайн-зависимости одной командой
4. Запустить `ansible-playbook site.yml` — и получить работающую платформу
5. Пройти приёмо-сдаточные тесты (`make test`)

### Критерии приёмки

- [ ] `make deploy` на чистой Astra Linux поднимает платформу за ≤ 1 час
- [ ] `make test` — все тесты проходят
- [ ] Документация позволяет администратору выполнить резервное копирование и восстановление
- [ ] Документация позволяет пользователю работать с чатом и API без дополнительных вопросов
- [ ] Все скрипты и playbooks идемпотентны (повторный запуск не ломает)
- [ ] Контрольные суммы всех файлов совпадают с `checksums.sha256`
