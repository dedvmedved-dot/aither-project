# Gap-анализ ТР → Фактическое железо

## Соответствие оборудования требованиям ТР

| Требование ТР | Фактически | Статус | Примечание |
|---|---|---|---|
| **2× сервер** | YADRO VEGMAN S320 × 2 | ✅ | Полное соответствие |
| **4× GPU RTX 6000** | 2× RTX 6000 на сервер | ⚠️ | **В 2 раза меньше** |
| **768 GB RAM** | 768 GB (12× 64 GB DDR4-2933) | ✅ | Идеально |
| **Хранилище** | 38.4 TB MegaRAID + 960 GB M.2 | ✅ | Даже больше |
| **10 GbE сеть** | Транк VLAN 308 | ✅ | |
| **RedOS 7.3** | Рекомендована 8.0.2 | ⚠️ | Обоснованно: драйвер 570 vs 535 |

## Узкие места и рекомендации

| Проблема | Влияние | Рекомендация |
|---|---|---|
| **2× GPU вместо 4× на сервер** | Модели > 48 GB не влезут в VRAM | LLaMA-70B-Q4 (40 GB) — OK. Для 70B-FP16 — нужно 2 сервера (tensor parallel) |
| **NVLink между GPU** | Единое адресное пространство 48 GB | Решает проблему моделей до 48 GB |
| **Диск 447 GB (текущий VD)** | Мало для ISO + ОС | Расширить через MegaRAID RAID1 из 2× 1.7 TB |
| **Отсутствие HA для etcd** | 2 ноды = риск split-brain | Добавить etcd на VPS (Witness) ИЛИ использовать 2-нодный кластер с external etcd |

## Что нужно изменить в ТР

1. **K3s → K8s**: обосновано — production GPU-кластер с NVLink требует полного Kubernetes
2. **4 GPU → 2 GPU (NVLink) на сервер**: tensor parallel между серверами для больших моделей
3. **RedOS 7.3 → 8.0.2**: драйвер NVIDIA 570 критичен для GPU Operator
4. **Портал → VPS2**: разместить Portal BFF + Portal DB на VPS2 (не на серверах)
5. **etcd external witness**: добавить etcd на VPS1/VPS2 для кворума при 2 нодах
