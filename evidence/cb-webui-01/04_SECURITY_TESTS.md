## Тест 10: CSRF-защита

**Результат:** ✅
- Все fetch-запросы используют `credentials: 'same-origin'`
- Это предотвращает отправку cookie на кросс-доменные запросы

```javascript
async function api(path, opts = {}) {
    const headers = { 'Content-Type': 'application/json', ...opts.headers };
    if (authToken && !path.startsWith('/auth/')) {
        headers['Authorization'] = 'Bearer ' + authToken;
    }
    try {
        const res = await fetch(API_URL + path, { ...opts, headers, credentials: 'same-origin' });

    }
}
```

## Тест 11: Безопасность token_id

**Описание:** `token_id` — это 12-символьный hex-идентификатор (`secrets.token_hex(6)`), используемый исключительно как первичный ключ в базе данных для ссылок на токены. Он **не является** секретом и **не пригоден** для аутентификации.

**Формат:**
```python
token_id = secrets.token_hex(6)  # 12 hex-символов, например "a1b2c3d4e5f6"
```

**Проверка безопасности:**

| Свойство | Значение | Статус |
|----------|----------|--------|
| Длина | 12 символов (96 бит энтропии как идентификатор) | ✅ |
| Не передаётся как Bearer-токен | Используется только в URL как идентификатор ресурса | ✅ |
| Не участвует в подписи/шифровании | Чисто идентификатор БД | ✅ |
| Не раскрывается в логах как секрет | Не является секретом | ✅ |
| Уникальность | Гарантируется `secrets.token_hex()` | ✅ |

**Что используется для аутентификации:**
- Для пользователей: сессионный токен (`sess_*`) + cookie
- Для агентов: Bearer-токен формата `athr_<urlsafe_base64>` (хешируется bcrypt/scrypt в БД)
- `token_id` — только для ссылок (например, `DELETE /api/v1/tokens/{token_id}`)
