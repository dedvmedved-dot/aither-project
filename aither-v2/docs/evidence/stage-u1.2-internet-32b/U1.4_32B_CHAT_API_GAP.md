# U1.4-GAP-32B-CHAT-001 — 32B Chat Completions API Gap

**ID:** U1.4-GAP-32B-CHAT-001  
**Area:** OpenAI-compatible API  
**Stage:** U1.4 (OpenAI-compatible API)  
**Severity:** BLOCKING for full 32B Chat Completions compatibility declaration  

---

## Current State

The 32B backend (`vllm-32b-gptq`) runs the model `qwen-32b-base` — a **base completion model** without chat/instruction fine-tuning.

### What works:
- `/v1/completions` (OpenAI legacy text completion) — 200 OK, returns coherent completions
- ai-platform adapter converts `/v1/chat/completions` → `/v1/completions` internally

### What doesn't work:
- Native `/v1/chat/completions` — blocked by nginx-gateway-32b with hardcoded HTTP 422:
  ```
  {"error":"qwen-32b-base does not support chat"}
  ```
- The ai-platform workaround (converting chat → completion) loses:
  - Multi-turn conversation context (only last message used as prompt)
  - System messages
  - Chat-specific response formatting (returns `text_completion` object, not `chat.completion`)

### Architecture detail:

```
nginx-gateway-32b ConfigMap:
  location = /v1/chat/completions {
      return 422 '{"error":"qwen-32b-base does not support chat"}';
  }
  location /v1/completions {
      proxy_pass http://10.99.3.103:8000;  # → vLLM 32B
  }
```

---

## Target State

A documented and stable OpenAI-compatible contract is available:
- `/v1/chat/completions` returns HTTP 200 with `chat.completion` object
- Multi-turn conversations are supported
- System messages are honored
