Route check: BFF upstream routing from app.py logic
Date: 2026-07-20 02:30 MSK

Source files:
  - tools/bff/app.py (source of truth)
  - manifests/mvp-roadmap/05-bff/bff-mvp.yaml (ConfigMap aither-bff-config)

Routes defined in app.py:

GET /health                          -> local handler (no upstream)
POST /api/v1/chat model=14b         -> http://vllm-14b-instruct.aither-inference.svc:8000/v1/chat/completions
POST /api/v1/chat model=32b         -> BLOCKED (422) before upstream
POST /api/v1/chat model=unknown     -> BLOCKED (400) before upstream
POST /api/v1/completions model=14b  -> http://vllm-14b-instruct.aither-inference.svc:8000/v1/completions
POST /api/v1/completions model=32b  -> http://nginx-gateway-32b.aither-inference.svc:8000/v1/completions
POST /api/v1/completions model=unknown -> BLOCKED (400) before upstream
GET /api/v1/models                  -> static list (no upstream call)

Authorization: forwarded from client Request headers to upstream if present.

Key design decisions:
- 32B chat blocked BEFORE upstream call (no traffic to vLLM 32B)
- 32B completion routed ONLY through nginx-gateway-32b (never direct to vllm-32b-gptq)
- 14B routes direct to vllm-14b-instruct (no gateway for 14B)
- No hardcoded secrets in app.py
