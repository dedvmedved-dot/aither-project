## Управление организациями

### Просмотр
Вкладка 🏢 **Организации** → таблица всех организаций с балансом, тарифом, количеством участников и API-ключей.

### Детали организации
Клик 👁 → карточка организации + список участников (роль, email).

### Удаление
Клик 🗑 → подтверждение → каскадное удаление:
- Участники (portal_org_members)
- API-ключи (portal_api_keys)
- Биллинг (billing_accounts)
- Платежи (payment_transactions)
- Политики (portal_org_policies — автоматически через ON DELETE CASCADE)
- Организация (portal_organizations)

### Именование
При регистрации организация получает имя `{displayName}-организация`.
Раньше было «Личный» — старые организации переименованы.

## Управление пользователями

### Просмотр
Вкладка 👥 **Пользователи** → таблица: имя, email, OAuth-провайдер, количество организаций.

### Организации пользователя
Клик 🏢 → список организаций, в которые входит пользователь (роль, тариф, баланс).

### Смена роли
Выпадающий список: owner / billing_admin / developer / viewer.
Устанавливает роль пользователя во всех его организациях.

### Удаление
Клик 🗑 → подтверждение → пользователь исключается из всех организаций и удаляется.
Чаты пользователя сохраняются.

## Управление API-ключами

Вкладка 🔑 **API-ключи** — таблица всех ключей:
- Префикс ключа (первые символы)
- Название ключа
- Организация-владелец
- Статус (active/revoked)
- Дата создания и последнего использования
- Кнопка 🚫 **Отозвать** для активных ключей

## Управление токенами

Вкладка 💰 **Токены**:
1. Выбрать организацию из выпадающего списка
2. Указать сумму
3. **+ Начислить** — пополнение баланса
4. **− Списать** — списание с баланса

## Настройка LDAP

Вкладка 🔧 **Настройки** → 9 полей:

| Поле | Пример |
|---|---|
| LDAP-сервер | `ldap://freeipa.example.com:389` |
| Базовый DN | `dc=example,dc=com` |
| Сервисная учётка (DN) | `uid=svc,cn=users,cn=accounts,...` |
| Пароль учётки | `••••••••` |
| User Base | `cn=users,cn=accounts,...` |
| Group Base | `cn=groups,cn=accounts,...` |
| Атрибут логина | `uid` |
| Атрибут почты | `mail` |
| Атрибут имени | `displayName` |

После сохранения — **перезапустить BFF**: `systemctl restart aither-bff`.

Ролевое сопоставление (группы LDAP → роли портала):
- `aither-admins` → owner
- `aither-billing` → billing_admin
- `aither-developers` → developer

## Технические детали

### BFF (VPS2)
```bash
systemctl status aither-bff    # статус
systemctl restart aither-bff   # перезапуск (после смены LDAP)
journalctl -u aither-bff -f    # логи
```

### Nginx (VPS2 Docker)
```bash
docker restart portal-portal-nginx-1  # перезапуск (после смены статики)
```

### Gateway (K8s)
```bash
kubectl get pods -l app=gateway
kubectl logs deploy/gateway
kubectl rollout restart deploy/gateway
```

### База данных (VPS2 Docker)
```bash
docker exec aither-portal-portal-db-1 psql -U portal -d portal
```
