Я
parsec.max_ilev=63 не дает поставить драйвера. Как установить драйвер?
Алиса
Параметр parsec.max_ilev=63 сам по себе не блокирует установку драйверов — он лишь задаёт максимальный уровень целостности для субъектов. Проблемы при установке драйверов в Astra Linux чаще связаны с комбинацией мандатного контроля целостности (МКЦ), мандатного разграничения доступа (МРД) и требований к исполняемому стеку.

Что проверить в первую очередь
Вход под максимальным уровнем целостности.
При входе в систему (в графической сессии Fly или в консоли) обязательно выбирайте уровень целостности «Высокий» (соответствует 63). Если войти под низким уровнем, даже sudo не даст обойти ограничения МКЦ на изменение защищённых объектов.
Уровень защищённости ОС.
Убедитесь, что включён нужный режим:
bash
sudo astra-modeswitch get
Для полноценной работы МКЦ нужен режим «Воронеж» (1) или «Смоленск» (2). В режиме «Орёл» механизмы защиты отключены.
Включен ли МКЦ.
Проверьте:
bash
cat /parsecfs/mic_enabled
Ожидаемое значение — 1. Если 0, включите:
bash
sudo astra-mic-control enable
sudo reboot
Частые причины, почему драйвер не ставится, и решения
Проблема: блокировка загрузки модулей ядра из‑за политик безопасности
В режимах «Воронеж/Смоленск» установка модулей ядра может блокироваться, если нарушаются правила МКЦ/МРД или если модуль требует execstack.

Что сделать:

Попробуйте установить драйвер стандартными средствами (через dkms, make install и т. п.) из сессии с уровнем целостности 63.
Если драйвер поставляется в виде .run/скрипта, запускайте его явно через bash в сессии с высоким уровнем целостности.
Проблема: драйвер требует включения execstack
Некоторые проприетарные драйверы (например, NVIDIA) требуют возможности использовать исполняемый стек. В Astra Linux это регулируется параметром ядра.

Решение:

Откройте /etc/default/grub.
В строке GRUB_CMDLINE_LINUX_DEFAULT добавьте (или убедитесь, что есть) параметр:
text
parsec.execstack=1
Пример итоговой строки:
text
GRUB_CMDLINE_LINUX_DEFAULT="parsec.max_ilev=63 parsec.execstack=1 quiet"
Обновите загрузчик:
bash
sudo update-grub
Перезагрузите систему и снова войдите под уровнем целостности «Высокий».
Важно: включение execstack снижает уровень защиты. Делайте это только для доверенных драйверов и по необходимости.

Если драйвер — модуль ядра (.ko)
После компиляции модуля:

Проверьте, что уровень целостности текущей сессии — 63:
bash
pdpl-whoami
Установите модуль:
bash
sudo insmod модуль.ko
# или
sudo modprobe модуль
Если получаете ошибку доступа, проверьте метки безопасности на каталоге модулей и самом файле:
bash
pdpl-file /lib/modules/$(uname -r)/kernel/drivers/ваш_драйвер/модуль.ko
При необходимости скорректируйте мандатные атрибуты (только если понимаете последствия):
bash
sudo pdpl-file -i 63:0:0x0:0 /путь/к/модулю.ko
Если используется DKMS
DKMS запускает сборку в своей среде, которая может не наследовать мандатный контекст корректно.

Рекомендации:

Выполняйте установку DKMS-драйвера из сессии с уровнем целостности 63.
Убедитесь, что у пользователя есть необходимые привилегии Parsec для работы с /usr/src и /lib/modules.
При ошибках смотрите логи: /var/log/syslog, dmesg, а также сообщения от подсистемы Parsec (часто выводятся в syslog).
Альтернатива: временно отключить МКЦ для проверки
Если нужно быстро проверить, что драйвер вообще работоспособен:

bash
sudo astra-mic-control disable
sudo reboot
После этого попробуйте установить драйвер. Если получится — проблема точно в политиках МКЦ/MRD, и нужно точечно настраивать мандатные атрибуты либо использовать parsec.execstack=1. После проверки верните МКЦ обратно:

bash
sudo astra-mic-control enable
sudo reboot
Критически важные нюансы
Никакой уровень целостности не «отключает» все проверки. Даже под 63 действуют мандатные метки конфиденциальности, замкнутая программная среда и другие механизмы — в зависимости от режима («Воронеж»/«Смоленск»).
Не меняйте parsec.max_ilev на значения выше 63. В текущей реализации 63 — максимальный уровень целостности; попытка задать большее значение не даст эффекта или приведёт к непредсказуемому поведению.
Изменение параметров ядра и политик безопасности — привилегированная операция. Делайте это только если вы администратор системы и понимаете риски.
Что нужно, чтобы подсказать точные команды
Чтобы дать максимально точные шаги, уточните:

Какой именно драйвер (NVIDIA, Realtek, кастомный модуль и т. д.) и в каком виде он поставляется (.deb, .run, исходный код, .ko).
Текущий уровень защищённости (astra-modeswitch get) и включён ли МКЦ (cat /parsecfs/mic_enabled).
Текст ошибки при установке (полный вывод терминала, особенно строки про Permission denied, Operation not permitted, сообщения ядра).
Тогда можно будет привести конкретный пример установки именно для вашего случая.
