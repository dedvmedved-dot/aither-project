## Назначение системы

**Aither AI Platform** — это платформа для работы с большими языковыми моделями (LLM) через веб-интерфейс и OpenAI-совместимый API. Платформа предоставляет:

- 💬 **Интерактивный чат** с моделями в реальном времени через браузер
- 🔑 **Централизованное управление API-ключами** — создание, просмотр, отзыв токенов доступа
- 🤖 **Подключение AI-агентов** — Claude Code, Codex, OpenCode, Hermes Agent и любых OpenAI-совместимых клиентов
- 🌐 **Двухзонный доступ** — Internet (HTTPS) и Test Zone (внутренняя сеть)

**Основные применения:**

| Сценарий | Модель | Способ |
|---|---|---|
| Диалоги, вопросы-ответы, инструкции | `qwen-14b` | Web UI / API |
| Написание кода, перевод, резюме | `qwen-14b` | Web UI / API |
| Продолжение и генерация текста | `qwen-32b-base` | Web UI / API |
| Автоматизация (скрипты, агенты) | `qwen-14b` (рекомендуется) | API |

## Зоны доступа

Aither предоставляет **две точки доступа** с идентичным функционалом. API-ключи и учётные записи — общие для обеих зон.

### Internet Zone: `https://fb1.spb.ru:443`

| Характеристика | Значение |
|---|---|
| **URL** | `https://fb1.spb.ru:443/` |
| **Доступ** | Открытый — из любой точки интернета |
| **Протокол** | HTTPS |
| **Сертификат** | Доверенный (Let's Encrypt), автоматическое обновление |
| **Порт** | 443 |
| **Бейдж в UI** | 🌐 **INTERNET** (зелёный) |
| **Безопасность** | Трафик шифруется. Подходит для любых сетей, включая публичные |

**Когда использовать:**
- ✅ Основная повседневная работа
- ✅ Доступ из дома, офиса, командировки
- ✅ Работа с конфиденциальными данными (HTTPS)
- ✅ Подключение AI-агентов через интернет

**Базовый URL для API:** `https://fb1.spb.ru:443`

### Test Zone: `http://10.129.13.78:30080`

| Характеристика | Значение |
|---|---|
| **URL** | `http://10.129.13.78:30080/` |
| **Доступ** | Только из внутренней сети или через VPN |
| **Протокол** | HTTP |
| **Сертификат** | Отсутствует |
| **Порт** | 30080 |
| **Бейдж в UI** | 🧪 **TEST ZONE** (жёлтый) |
| **Безопасность** | Без шифрования — только внутри защищённой сети |

**Когда использовать:**
- ✅ Доступ из внутренней сети организации
- ✅ Тестирование из изолированной среды
- ✅ Когда Internet-доступ заблокирован (брандмауэры, CGNAT)

**Базовый URL для API:** `http://10.129.13.78:30080`

> 💡 **Зона определяется автоматически** по URL, через который вы вошли. Бейдж зоны отображается на панели управления и в верхней части всех страниц.

## Вход в систему

### Пошаговая инструкция

1. **Откройте браузер** Chromium или Firefox
2. **Перейдите по адресу:**
   - Internet: `https://fb1.spb.ru:443/`
   - Test Zone: `http://10.129.13.78:30080/`
3. **Введите учётные данные** (выдаются администратором):
   - Имя пользователя (логин)
   - Пароль
4. **Нажмите «Войти»**

### После успешного входа

Вы попадаете на **панель управления (Dashboard)**. Система создаёт сессию, которая сохраняется до выхода или закрытия браузера.

### При ошибке входа

| Проблема | Возможная причина | Решение |
|---|---|---|
| «Неверный логин или пароль» | Опечатка в учётных данных | Проверьте логин и пароль, попробуйте снова |
| Страница не открывается | Проблема с сетью или URL | Проверьте подключение к интернету, правильность URL |
| «Ошибка авторизации» | Повреждённые cookies | Очистите cookies браузера, попробуйте снова |
| Бесконечная загрузка | Блокировка скриптов | Проверьте, что JavaScript включён |
| Предупреждение о сертификате | Неверный URL | Используйте `https://fb1.spb.ru:443/` (не IP-адрес). Сертификат Let's Encrypt — доверенный |

> 💡 Если проблема сохраняется — обратитесь к администратору. Не пытайтесь подбирать пароль многократно — учётная запись может быть временно заблокирована.

## Чат с моделями

### Открытие чата

1. Нажмите **💬 Чат** в верхнем меню
2. Откроется интерфейс диалога с полем ввода и историей сообщений

### Выбор модели: MODEL_A и MODEL_B

В верхней части страницы чата расположен **выпадающий список моделей**. Платформа предоставляет две модели:

| Идентификатор | Название в UI | Тип | Бейдж | Для чего |
|---|---|---|---|---|
| `qwen-14b` | **MODEL_A** | Instruct (чат) | `Чат` | Диалоги, вопросы-ответы, следование инструкциям |
| `qwen-32b-base` | **MODEL_B** | Base (completion) | `Базовая` | Продолжение и генерация текста |

**Как выбрать модель:**
1. Нажмите на выпадающий список в верхней части чата
2. Выберите нужную модель
3. Рядом с селектором отобразится подсказка о типе выбранной модели

> ⚠️ **При смене модели** история диалога сохраняется, но контекст может быть некорректным для новой модели. Рекомендуется нажать **«Очистить»** при переключении.

### Параметры запроса

Перед отправкой сообщения можно настроить параметры генерации:

| Параметр | Описание | Диапазон | По умолчанию |
|---|---|---|---|
| **max_tokens** | Максимальная длина ответа в токенах | 1–4096 | 2048 |
| **temperature** | «Креативность»: 0.0 = точный ответ, 1.0+ = творческий | 0.0–2.0 | 0.7 |

**Рекомендации по параметрам:**

| Задача | temperature | max_tokens |
|---|---|---|
| Точный ответ, код, факты | 0.1–0.3 | 512–1024 |
| Общий диалог | 0.5–0.7 | 1024–2048 |
| Творческое письмо | 0.8–1.2 | 2048+ |

### Отправка сообщений

1. **Выберите модель** в выпадающем списке
2. **Введите текст** в поле ввода
3. **Отправьте сообщение:**
   - Нажмите клавишу **Enter**
   - Или нажмите кнопку **▶ Отправить**
4. **Дождитесь ответа** — отображается индикатор загрузки
5. **Ответ модели** появится в истории диалога

> 💡 Поддерживается **история диалога** в рамках сессии. Модель «помнит» предыдущие сообщения в текущем диалоге. При очистке чата или выходе история удаляется.

### Действия с ответом

| Кнопка | Действие | Когда использовать |
|---|---|---|
| 📋 **Копировать** | Копирует текст ответа в буфер обмена | Сохранить ответ для использования в другом месте |
| 🗑️ **Очистить** | Очищает всю историю текущего диалога | Начать новый диалог, сменить тему |

### Особенности моделей

#### MODEL_A — `qwen-14b` (чат-модель)

| Характеристика | Значение |
|---|---|
| Тип | Instruct (оптимизирована для диалогов) |
| Контекстное окно | 4096 токенов |
| Языки | Русский, английский, китайский |
| Поведение | Отвечает на вопросы, следует инструкциям, ведёт диалог |

**Примеры запросов:**
- *«Напиши функцию на Python для сортировки списка словарей по ключу»*
- *«Переведи на английский: Добро пожаловать в Aither»*
- *«Объясни, что такое контекстное окно языковой модели»*

#### MODEL_B — `qwen-32b-base` (базовая модель)

| Характеристика | Значение |
|---|---|
| Тип | Base (для продолжения текста) |
| Контекстное окно | 4096 токенов |
| Языки | Русский, английский, китайский |
| Поведение | Продолжает текст с того места, где остановился пользователь |

**⚠️ Важно:** `qwen-32b-base` — базовая модель, **не оптимизированная для диалогов**. Она продолжает текст, а не «отвечает» на вопросы. Для общения всегда используйте `qwen-14b`.

**Примеры запросов (начало текста для продолжения):**
- *«Продолжи: Искусственный интеллект — это область компьютерных наук, которая...»*
- *«Продолжи: Однажды в студёную зимнюю пору я из лесу вышел...»*
- *«Напиши продолжение: Глава 1. Рассвет нового мира»*

## Управление API-ключами

### Что такое API-ключ?

**API-ключ (токен)** — персональный идентификатор для доступа к моделям Aither через API. Используется:
- В скриптах автоматизации (Python, bash, PowerShell)
- AI-агентами (Claude Code, Codex, OpenCode, Hermes Agent)
- Любыми OpenAI-совместимыми клиентами

**Формат ключа:**
```
athr_<префикс>_<секретная_часть>
```
- `athr_` — обязательный префикс всех ключей платформы
- `<префикс>` — 8 символов для идентификации (отображается в Web UI)
- `<секретная_часть>` — длинная случайная строка (секрет)

> 🔐 **Для обычной работы через Web UI ключ не нужен.** API-ключи — только для программного доступа.

### Просмотр списка ключей

1. Перейдите в раздел **🔑 API Ключи** в верхнем меню
2. Откроется таблица со всеми вашими ключами:

| Колонка | Описание |
|---|---|
| **Название** | Имя, заданное при создании (например, «KEY_A: чат-скрипт») |
| **Префикс** | Первые 13 символов ключа (`athr_XXXXXXXX`) |
| **Модели** | Какие модели доступны: Все / Только 14B / Только 32B |
| **Статус** | 🟢 Активен / 🔴 Отозван |
| **Создан** | Дата и время создания |
| **Использован** | Дата и время последнего запроса с этим ключом |

> 💡 По префиксу можно идентифицировать ключ (например, для отзыва), но **нельзя восстановить полный ключ**.

### Создание KEY_A (ключ только для 14B)

**KEY_A** — API-ключ, дающий доступ **только к модели `qwen-14b`**. Используется для чат-агентов и диалоговых сценариев.

**Пошаговая инструкция:**

1. **Перейдите в раздел 🔑 API Ключи**
2. **Нажмите «+ Создать новый ключ»** — откроется форма создания
3. **Заполните поля:**
   - **Название:** `KEY_A: ...` (например, `KEY_A: чат-агент`, `KEY_A: Python-скрипт`)
   - **Модели:** выберите **«Только 14B»** (модель `qwen-14b`)
4. **Нажмите «Создать»**
5. **⚠️ СКОПИРУЙТЕ ПОЛНЫЙ КЛЮЧ** — он будет показан только один раз (см. [Однократный показ секрета](#однократный-показ-секрета))
6. **Сохраните ключ в надёжном месте**

**Пример использования KEY_A:**
```bash
# Chat completions — работает
curl https://fb1.spb.ru:443/v1/chat/completions \
  -H "Authorization: Bearer athr_a1b2c3d4_..." \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen-14b","messages":[{"role":"user","content":"Привет!"}]}'
```

> 🔒 KEY_A даёт доступ **только** к `qwen-14b`. Запросы к `qwen-32b-base` с этим ключом вернут HTTP 401.

### Создание KEY_B (ключ только для 32B)

**KEY_B** — API-ключ, дающий доступ **только к модели `qwen-32b-base`**. Используется для сценариев продолжения текста.

**Пошаговая инструкция:**

1. **Перейдите в раздел 🔑 API Ключи**
2. **Нажмите «+ Создать новый ключ»**
3. **Заполните поля:**
   - **Название:** `KEY_B: ...` (например, `KEY_B: генератор текста`, `KEY_B: completion-скрипт`)
   - **Модели:** выберите **«Только 32B»** (модель `qwen-32b-base`)
4. **Нажмите «Создать»**
5. **⚠️ СКОПИРУЙТЕ ПОЛНЫЙ КЛЮЧ**
6. **Сохраните ключ в надёжном месте**

**Пример использования KEY_B:**
```bash
# Completion через chat/completions — работает
curl https://fb1.spb.ru:443/v1/chat/completions \
  -H "Authorization: Bearer athr_e5f6g7h8_..." \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen-32b-base","messages":[{"role":"user","content":"Продолжи: Искусственный интеллект — это"}],"max_tokens":100}'
```

> 🔒 KEY_B даёт доступ **только** к `qwen-32b-base`. Запросы к `qwen-14b` с этим ключом вернут HTTP 401.

### Создание универсального ключа (обе модели)

Если нужен доступ к обеим моделям — при создании выберите **«Обе (14B и 32B)»**. Такой ключ работает с `qwen-14b` и `qwen-32b-base`.

**Рекомендуется** для AI-агентов, которым может потребоваться переключение между моделями.

### Однократный показ секрета

**⚠️ КРИТИЧЕСКИ ВАЖНО:** Полный API-ключ показывается **ровно один раз** — сразу после создания.

- После закрытия окна создания **восстановить полный ключ невозможно**
- В таблице ключей отображается **только префикс** (`athr_XXXXXXXX`)
- Система **не хранит** секретную часть в открытом виде

> Если вы не сохранили полный ключ — **отзовите его** и создайте новый. Восстановить полный ключ нельзя по соображениям безопасности.

### Безопасное копирование ключа

**При создании ключа:**

1. **Нажмите кнопку 📋 Копировать** рядом с отображаемым ключом — или выделите текст и скопируйте (Ctrl+C / Cmd+C)
2. **Немедленно сохраните** в одном из безопасных мест:

| Способ хранения | Команда / Пример | Безопасность |
|---|---|---|
| Переменная окружения | `export AITHER_API_KEY="athr_..."` | ✅ Рекомендуется |
| Файл `.env` (в .gitignore) | `AITHER_API_KEY=athr_...` | ✅ Рекомендуется |
| Менеджер паролей | Bitwarden, 1Password, KeePass | ✅ Рекомендуется |
| Файл `~/.aither_token` | `echo "athr_..." > ~/.aither_token && chmod 600 ~/.aither_token` | ✅ Приемлемо |

3. **Проверьте,** что ключ скопировался **полностью** — без лишних пробелов, переносов строк и обрезания
4. **Закройте окно** создания ключа

**❌ Никогда:**
- Не вставляйте ключ прямо в исходный код
- Не сохраняйте ключ в файлы, которые попадают в Git
- Не передавайте ключ через мессенджеры и email
- Не публикуйте скриншоты с полным ключом

### Отзыв (revoke) ключа

Отзыв делает ключ **немедленно недействительным**. Все запросы с отозванным ключом вернут HTTP 401.

**Когда нужно отозвать ключ:**
- Ключ скомпрометирован (попал в Git, чат, скриншот)
- Ключ потерян (не сохранили при создании)
- Ключ больше не нужен (проект завершён, агент отключён)
- Подозрение на несанкционированное использование

**Пошаговая инструкция:**

1. **Перейдите в раздел 🔑 API Ключи**
2. **Найдите нужный ключ** в таблице по названию или префиксу
3. **Нажмите «Отозвать»** в строке ключа
4. **Подтвердите действие** в диалоговом окне
5. Статус изменится с 🟢 Активен на 🔴 Отозван

**После отзыва:**
- Все запросы с этим ключом немедленно отклоняются
- Восстановить отозванный ключ **нельзя**
- Можно создать новый ключ с теми же правами доступа

## Подключение AI-агентов

AI-агенты (Claude Code, OpenAI Codex, OpenCode, Hermes Agent) подключаются к Aither через API-ключ как к OpenAI-совместимому провайдеру.

### Быстрая настройка (универсальный способ)

1. **Создайте API-ключ** в разделе 🔑 API Ключи (рекомендуется: **обе модели**)
2. **Установите переменные окружения:**

```bash
export OPENAI_API_KEY="athr_..."
export OPENAI_BASE_URL="https://fb1.spb.ru:443/v1"
```

3. **Запустите агента.** Большинство агентов автоматически подхватят эти переменные.

### Настройка конкретных агентов

#### Claude Code
```bash
npm install -g @anthropic-ai/claude-code
export OPENAI_API_KEY="athr_..."
export OPENAI_BASE_URL="https://fb1.spb.ru:443/v1"
claude
```

#### OpenAI Codex CLI
```bash
npm install -g @openai/codex
export OPENAI_API_KEY="athr_..."
export OPENAI_BASE_URL="https://fb1.spb.ru:443/v1"
codex --model qwen-14b
```

#### OpenCode
```bash
pip install opencode
export OPENAI_API_KEY="athr_..."
export OPENAI_BASE_URL="https://fb1.spb.ru:443/v1"
opencode --model qwen-14b
```

#### Hermes Agent
```bash
hermes config set provider.aither.api_key "athr_..."
hermes config set provider.aither.base_url "https://fb1.spb.ru:443/v1"
hermes config set provider.aither.models '["qwen-14b", "qwen-32b-base"]'
hermes config set model "aither/qwen-14b"
```

#### Python (openai library)
```python
from openai import OpenAI
import os

client = OpenAI(
    api_key=os.environ["AITHER_API_KEY"],        # athr_...
    base_url="https://fb1.spb.ru:443/v1"
)

response = client.chat.completions.create(
    model="qwen-14b",
    messages=[{"role": "user", "content": "Привет!"}]
)
print(response.choices[0].message.content)
```

### Рекомендации для агентов

| Рекомендация | Почему |
|---|---|
| Используйте `qwen-14b` | Лучше следует инструкциям, оптимизирована для диалогов |
| Создавайте отдельный ключ на каждого агента | Можно отозвать один ключ, не затрагивая другие |
| Не превышайте контекст в 3000 слов | Контекстное окно — 4096 токенов |
| Не запускайте одновременно 4+ агентов | Запросы к 14B встают в очередь GPU |

### Проверка подключения

```bash
curl https://fb1.spb.ru:443/v1/models \
  -H "Authorization: Bearer athr_..."
```

Ожидаемый ответ (HTTP 200):
```json
{
  "object": "list",
  "data": [
    {"id": "qwen-14b", "object": "model", "owned_by": "aither"},
    {"id": "qwen-32b-base", "object": "model", "owned_by": "aither"}
  ]
}
```

## Работа через обе зоны

Aither предоставляет две зоны доступа, и вы можете использовать обе:

### С Web UI

- Откройте Internet в одной вкладке браузера: `https://fb1.spb.ru:443/`
- Откройте Test Zone в другой вкладке: `http://10.129.13.78:30080/`
- Используйте **те же логин и пароль**
- Сессии в разных зонах **независимы**

### С API

Один API-ключ работает в обеих зонах. Различается только базовый URL:

```bash
# Internet
curl https://fb1.spb.ru:443/v1/models \
  -H "Authorization: Bearer athr_..."

# Test Zone
curl http://10.129.13.78:30080/v1/models \
  -H "Authorization: Bearer athr_..."
```

### С AI-агентами

| Где работает агент | Какой URL использовать |
|---|---|
| В интернете | `https://fb1.spb.ru:443/v1` |
| Во внутренней сети / VPN | `http://10.129.13.78:30080/v1` |

API-ключ один и тот же. Меняйте только `base_url` в настройках агента.

> 💡 **Совет:** Храните базовый URL в переменной окружения:
> ```bash
> export AITHER_BASE_URL="https://fb1.spb.ru:443"     # Internet
> # export AITHER_BASE_URL="http://10.129.13.78:30080" # Test Zone
> ```

## Выход из системы

**Пошаговая инструкция:**

1. Нажмите кнопку **«Выйти»** (обычно в правом верхнем углу, рядом с именем пользователя)

**Важные замечания:**

- Для завершения работы закройте браузер — особенно на общих компьютерах

## Безопасность ключей

### Основные правила

| ✅ Правильно | ❌ Неправильно |
|---|---|
| Хранить ключ в переменной окружения | Хардкодить ключ в коде |
| Отдельный ключ для каждой цели | Один ключ на всё |
| Отзывать неиспользуемые ключи | Хранить «на всякий случай» |
| Использовать менеджер паролей | Записывать в открытом тексте |
| Добавить `.env` в `.gitignore` | Коммитить ключи в Git |
| Хранить base_url в конфигурации | Менять URL в каждом скрипте |

### При компрометации

Если ключ был случайно опубликован (GitHub, чат, скриншот) или вы подозреваете несанкционированный доступ:

1. 🛑 **Немедленно отзовите ключ** — 🔑 API Ключи → «Отозвать»
2. 📞 **Сообщите администратору** — через канал обратной связи
3. 🔑 **Создайте новый ключ** — 🔑 API Ключи → «+ Создать новый ключ»
4. 🔄 **Обновите ключ** во всех скриптах и агентах

### Безопасность браузера

- ✅ Выходите из системы на общих компьютерах
- ✅ Не сохраняйте пароль в браузере на чужих устройствах
- ✅ Используйте приватный режим (Incognito) на общих компьютерах
- ✅ Закрывайте браузер после завершения работы
- ❌ Не оставляйте открытую сессию без присмотра

## Поиск и устранение неисправностей

### Web UI

| Проблема | Проверьте | Решение |
|---|---|---|
| Страница не открывается | URL, интернет | Проверьте адрес, подключение к интернету |
| Не работает вход | Логин/пароль | Проверьте учётные данные, cookies |
| Чат не отправляет | Подключение, JS | Обновите страницу (F5), включите JavaScript |
| Модель не отвечает | Статус системы | Проверьте статус на панели управления |
| Ошибка авторизации | Сессия | Выйдите и войдите заново |
| Белый экран / вёрстка | Браузер | Используйте Chromium или Firefox |

### API-ключи

| Проблема | Проверьте | Решение |
|---|---|---|
| HTTP 401 | Ключ, формат | Проверьте префикс `athr_`, заголовок `Bearer` |
| HTTP 401 (ключ был рабочим) | Статус ключа | Проверьте в 🔑 API Ключи — не отозван ли? |
| HTTP 404 | Модель | Доступны только `qwen-14b` и `qwen-32b-base` |
| HTTP 429 | Частота запросов | Лимит 300/мин — подождите минуту |
| HTTP 500 | Сервер | Повторите позже, сообщите если повторяется |
| HTTP 504 | Таймаут | Модель не ответила вовремя, повторите |
| Ключ «не видит» модель | Права ключа | Проверьте, какие модели выбраны при создании |

### AI-агенты

| Проблема | Проверьте | Решение |
|---|---|---|
| Агент не подключается | URL, ключ | Проверьте `OPENAI_BASE_URL` (должен заканчиваться на `/v1`) |
| Плохие ответы | Модель | Используйте `qwen-14b` для агентов, не `qwen-32b-base` |
| Ответы обрезаны | max_tokens | Увеличьте лимит токенов в настройках агента |
| Таймауты | Нагрузка | Слишком много одновременных запросов — уменьшите число агентов |

### Общие рекомендации

1. **Обновите страницу (F5)** — первое, что стоит попробовать
2. **Очистите cookies** — если ошибка авторизации
3. **Попробуйте другой браузер** — для исключения проблем совместимости
4. **Проверьте подключение к интернету** — `ping fb1.spb.ru`
5. **Проверьте статус системы** на панели управления
6. **Сообщите администратору** — если проблема повторяется систематически
