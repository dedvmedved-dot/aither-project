# Aither — Алгоритм работы в Web UI (пошаговый)

**Версия:** CB-WEBUI-01-R1 · **Дата:** 26 июля 2026

## 8. Настройка агента (Configure agent)

| Шаг | Действие пользователя | Элемент Web UI | Ожидаемый результат | Возможная ошибка | Действие при ошибке |
|-----|----------------------|----------------|---------------------|------------------|---------------------|
| 8.1 | Определить, какой агент используется | — | Примеры: Claude Code, Codex CLI, OpenCode, Hermes Agent, Python-клиент (openai). | — | — |
| 8.2 | Настроить переменные окружения агента | Терминал | См. варианты ниже. | — | — |

### 8.2a — Вариант: Claude Code / Codex CLI / OpenCode

```bash
export OPENAI_API_KEY="$AITHER_API_KEY_14B"
export OPENAI_BASE_URL="https://fb1.spb.ru:443/v1"
```

### 8.2b — Вариант: Hermes Agent

```bash
hermes config set provider.aither.api_key "$AITHER_API_KEY_14B"
hermes config set provider.aither.base_url "https://fb1.spb.ru:443/v1"
hermes config set provider.aither.models '["qwen-14b", "qwen-32b-base"]'
hermes config set model "aither/qwen-14b"
```

### 8.2c — Вариант: Python (openai library)

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["AITHER_API_KEY_14B"],
    base_url="https://fb1.spb.ru:443/v1"
)
```

| 10.4 | Проверить ответ агента | Интерфейс агента | Модель продолжает текст. Стиль ответа — completion (отличается от диалогового стиля qwen-14b). | Ответ выглядит как «обрывок диалога» | Это ожидаемое поведение базовой модели. Для чата — переключить агента обратно на `qwen-14b` (шаг 9.1). |
| 10.5 | Проверить дату использования KEY_B в Web UI | Таблица ключей | Для ключа KEY_B отображается актуальная дата последнего запроса. | — | — |

## 11. Отзыв ключа (Revoke key)

| Шаг | Действие пользователя | Элемент Web UI | Ожидаемый результат | Возможная ошибка | Действие при ошибке |
|-----|----------------------|----------------|---------------------|------------------|---------------------|
| 11.1 | Перейти на страницу API-ключей | `.nav-link[data-page="api-keys"]` | Таблица со всеми ключами пользователя. | «Не удалось загрузить ключи.» | F5, проверить статус системы. |
| 11.2 | Найти ключ KEY_B в таблице | Строка таблицы с KEY_B | Видна строка: название `KEY_B_completion`, префикс `athr_YYYYYYYY`, статус 🟢 Активен. | Ключ не найден | Проверить, не был ли он уже отозван. |
| 11.3 | Нажать кнопку «Отозвать» для KEY_B | Кнопка «Отозвать» в строке ключа | Появляется диалог подтверждения: «Отозвать этот ключ? Это действие нельзя отменить.» | Кнопка неактивна (ключ уже отозван) | Если ключ уже отозван — действие не требуется. |
| 11.4 | Подтвердить отзыв | Кнопка «OK» / «Подтвердить» в диалоге | API-вызов `DELETE /api/v1/tokens/{token_id}`. Статус ключа меняется на 🔴 Отозван. Кнопка «Отозвать» исчезает или становится неактивной. | «Ошибка при отзыве ключа» | Попробовать снова. Проверить консоль браузера (F12 → Console) на наличие ошибок. |
| 11.5 | Убедиться, что KEY_A остался активным | Таблица ключей | KEY_A (14B) сохраняет статус 🟢 Активен. Отзыв одного ключа не затрагивает другие. | KEY_A тоже отозван | Проверить, что была нажата кнопка «Отозвать» именно для KEY_B. Если KEY_A отозван по ошибке — создать новый ключ (шаг 4). |

## 12. Проверка отказа в доступе (Verify denial)

| Шаг | Действие пользователя | Элемент Web UI | Ожидаемый результат | Возможная ошибка | Действие при ошибке |

| 12.1 | Попытаться использовать отозванный ключ KEY_B | Терминал (curl) | `curl -s https://fb1.spb.ru:443/v1/models -H "Authorization: Bearer $AITHER_API_KEY_32B"` возвращает HTTP 401 Unauthorized. Доступ запрещён. | Запрос возвращает HTTP 200 (ключ всё ещё работает) | Подождать ~5 сек — отзыв может применяться с небольшой задержкой. Проверить статус ключа в Web UI: должен быть 🔴 Отозван. | 12.2 | Попытаться выполнить чат-запрос с отозванным ключом | Терминал (curl) | `POST /v1/chat/completions` с KEY_B возвращает HTTP 401. Тело ответа содержит сообщение об ошибке аутентификации. | HTTP 200 (ключ работает) | Повторить отзыв ключа в Web UI. Убедиться, что подтвердили действие. |

| 12.4 | Проверить статус KEY_B в Web UI | Таблица ключей | Статус KEY_B: 🔴 Отозван. Колонка «Использован» показывает дату последнего использования (до отзыва). | Статус не обновился | Нажать F5. |

## Типовые ошибки и их решение (сводная таблица)

| Ошибка | Вероятная причина | Быстрое решение |
|---|---|---|
| Страница не загружается | Сеть недоступна / неверный URL | Проверить `https://fb1.spb.ru:443/`. Попробовать `http://10.129.13.78:30080/` |
| «Неверное имя пользователя или пароль» | Опечатка, Caps Lock, неверная раскладка | Проверить ввод. Обратиться к администратору |
| «Ошибка авторизации. Войдите заново.» | Сессия истекла / повреждена | Выйти → очистить cookies → войти заново |
| «Модель или endpoint не найден.» | Неверная модель / endpoint недоступен | Проверить выбор модели в селекторе. Проверить статус системы |
| «Превышен лимит запросов.» | Слишком много запросов (rate limit 300/мин) | Подождать 60 секунд |
| «Таймаут — модель не успела ответить.» | Высокая нагрузка на GPU | Повторить позже |
| `401 Unauthorized` (API) | Неверный / отозванный ключ | Проверить ключ. Создать новый в Web UI |
| `Connection refused` (API) | Неверный URL | Проверить `AITHER_BASE_URL` / `OPENAI_BASE_URL` |
| Ключ не копируется | Старый браузер / блокировка clipboard | Выделить вручную, Ctrl+C |
| Забыл скопировать полный ключ | Закрыто модальное окно | Отозвать ключ → создать новый. Полный ключ восстановить **нельзя** |
| Агент возвращает бессмыслицу | Используется 32B вместо 14B | Переключить агента на `qwen-14b` |
| Отозванный ключ всё ещё работает | Задержка синхронизации | Подождать ~5 сек, проверить статус в Web UI |
| После выхода страницы всё ещё доступны | Cookies не очищены | Очистить cookies вручную (DevTools → Application) |
