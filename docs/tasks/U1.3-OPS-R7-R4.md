# 9. Общие запреты

## 9.1. Запрет premature completion

Hermes запрещено объявлять completion, если:

* хотя бы один checkbox не `DONE`;
* отсутствует один evidence file;
* существует один unresolved credential;

* один required matrix case отсутствует;
* один process остаётся активным;
* регистрация не работает;
* Critical Gate не выполнен;
* Critical Gate не включает все направления.

## 9.2. Запрет narrative substitution

Запрещено считать доказательством фразы:

```text
deployed successfully
verified healthy
tests passed
foreground run
single runner
all artifacts consistent
credential revoked
security findings resolved
Hermes stopped
```

Каждое такое утверждение должно иметь committed raw evidence.

## 9.3. Запрет selective evidence

Запрещено:

* коммитить только успешный JUnit;
* скрывать failed log;
* удалять failed artifacts;
* выбирать лучший из нескольких запусков;
* называть неудачный запуск stale без регистрации его статуса;
* создавать JUnit вручную;
* изменять JUnit вручную;
* изменять JSON summary вручную;
* использовать exit code другого процесса;
* смешивать artifacts разных запусков.

## 9.4. Запрет retry-until-pass

При failure Hermes обязан:

1. сохранить failed evidence;
2. выполнить RCA;
3. исправить root cause;
4. создать новый implementation commit;
5. развернуть новый SHA;
6. выполнить новый полный run;
7. отметить старый run `SUPERSEDED`.

Запрещено бесконечно перезапускать неизменённый код до случайного PASS.

## 9.5. Запрет weakening

Запрещено:

* удалять assertions;
* заменять equality на substring;
* заменять hash на приблизительное сравнение;
* добавлять skip;
* добавлять xfail;
* добавлять conditional pass;
* снижать число browsers;
* снижать число zones;
* снижать число replicas;
* снижать число timing points;
* исключать отрицательные сценарии;
* считать отсутствие exception успешным тестом.

## 9.6. Запрет fixed sleep

Запрещено использовать:

```python
page.wait_for_timeout(...)
time.sleep(...)
asyncio.sleep(...)
```

как способ определить завершение network operation, model response, session invalidation или revoke propagation.

Sleep допустим только:

* как измеряемая точка обязательной revoke matrix;
* как backoff внутри явно ограниченного polling helper;
* при наличии deadline;
* при наличии condition check;
* при сохранении каждого результата.

## 9.7. Запрет runtime-only fixes

Запрещено:

* редактировать live container;
* редактировать ConfigMap без source change;
* применять hot patch без commit;
* тестировать uncommitted runtime;
* развёртывать code, отсутствующий в repository;
* оставлять deployed state, который нельзя воспроизвести из Git.

## 9.8. Запрет опасных Git-операций

# 10. Mandatory Direction 01

# Strict model-switch contract

## 10.1. Требуемая реализация

Реализовать сквозной идентификатор:

```text
client_request_id
```

Он должен создаваться Portal до отправки сообщения и передаваться через:

```text
Portal
→ HTTP request
→ BFF
→ backend request context
→ BFF response
→ Portal response handler
→ DOM message
```

Для каждого сообщения должны существовать:

```text
client_request_id
message_id
model_requested
model_resolved
status
created_at
completed_at
```

## 10.2. Обязательные проверки

Для первого запроса:

1. отправлен MODEL_A;
2. создан уникальный `client_request_id`;
3. placeholder связан с request ID;
4. response связан с тем же ID;
5. `model_resolved=MODEL_A`;
6. message count увеличился ровно на один;
7. response completed;
8. placeholder удалён;
9. вычислен SHA-256 нормализованного response;
10. stable `message_id` сохранён.

Для второго запроса:

1. создан другой request ID;
2. отправлен MODEL_B;
3. response связан со вторым ID;
4. `model_resolved=MODEL_B`;
5. message count увеличился ещё ровно на один;
6. первый message ID остаётся;
7. SHA-256 первого response не изменился;
8. второй response substantive;
9. duplicate assistant messages отсутствуют;
10. unresolved placeholders отсутствуют.

## 10.3. Matrix

```text
Internet × Chromium
Internet × Firefox
Test Zone × Chromium
Test Zone × Firefox
```

Required:

```text
4 passed
0 failed
0 skipped
0 xfailed
exit_code=0
```

## 10.4. Запрещено

* использовать `.last` как единственную корреляцию;
* проверять только outgoing request model;
* не проверять backend-resolved model;
* использовать substring вместо hash;
* использовать fixed sleep;
* создавать новый DOM ID при замене placeholder на completed response;
* считать test strict, если request ID отсутствует.

# 27. Mandatory Direction 18

# Secure self-registration

## 27.1. Целевой пользовательский сценарий

На странице входа должна находиться кнопка:

```text
Регистрация
```

Пользователь должен самостоятельно:

1. открыть форму регистрации;
2. ввести желаемый логин;
3. ввести пароль;
4. повторить пароль;
5. ввести одноразовый invite code;
6. отправить форму;
7. получить созданную учётную запись;
8. выполнить вход с выбранными логином и паролем.

Для limited beta применяется:

```text
invite-based self-registration
```

Это означает:

* пользователь сам выбирает логин;
* пользователь сам выбирает пароль;
* регистрация доступна только с одноразовым invite code;
* публичное неограниченное создание аккаунтов запрещено;
* созданная учётная запись получает только роль `registered_user`.

* atomic username uniqueness;
* atomic invite consumption;
* no duplicate users;
* shared visibility между replicas;

* Redis failure → 503;

Ключевое изменение процесса: **Hermes больше не должен определять завершение по факту прохождения тестов. Завершение определяется только состоянием чеклиста `18/18 DONE`, полнотой committed evidence и нулевым Critical Gate.** Передавайте задание целиком.
