## Функциональные ограничения

### `/v1/completions` недоступен

Эндпоинт `POST /v1/completions` возвращает HTTP 404 на обоих портах (:443, :10443).

**Workaround:** Используйте `POST /v1/chat/completions` для обеих моделей:
- `qwen-14b` — работает как чат
- `qwen-32b-base` — работает как completion (через chat-интерфейс)

**Статус:** Запланировано к исправлению.

---

### Нет потоковой передачи (streaming)

Параметр `"stream": true` не поддерживается. Ответ приходит целиком после завершения генерации.

**Влияние:** При длинных ответах пользователь ждёт весь ответ, не видя промежуточных результатов.

---

### Нет истории диалогов

Система **stateless** — не сохраняет историю между запросами. Каждый запрос обрабатывается независимо.

**Workaround:** Передавайте историю в массиве `messages` самостоятельно:
```json
{
  "messages": [
    {"role": "user", "content": "Вопрос 1"},
    {"role": "assistant", "content": "Ответ 1"},
    {"role": "user", "content": "Вопрос 2"}
  ]
}
```

---

### Нет function calling / tool use

Модель не может вызывать внешние функции или API. Только текст → текст.

---

### Нет загрузки файлов

API принимает только JSON. Загрузка файлов (изображения, документы) не поддерживается.

## Ограничения моделей

### qwen-32b-base — базовая модель

Модель **не оптимизирована для диалогов**. Она продолжает текст, а не «отвечает».

**Что это значит:**
- Ответы могут быть не в формате «вопрос-ответ»
- Модель может «уходить в сторону» от темы
- Качество диалога ниже, чем у qwen-14b

**Рекомендация:** Для диалогов всегда используйте `qwen-14b`.

---

### Контекстное окно: 4096 токенов

Обе модели имеют контекстное окно 4096 токенов (~3000–3500 слов).

При превышении:
- Старые сообщения игнорируются
- Модель «забывает» начало диалога

---

### Очередь GPU на 14B

Модель `qwen-14b` использует GPU последовательно. При нескольких одновременных запросах:

- Запросы выстраиваются в очередь
- 1-й запрос: ~5 сек
- 4-й запрос: ~20 сек
- 10-й запрос: ~50 сек

**Рекомендация:** Делайте паузы между запросами при интенсивном использовании.

## Инфраструктурные ограничения

### Самоподписанный SSL-сертификат

Сертификат не от публичного CA. Требуется:
- curl: `-k` (--insecure)
- Python: `verify=False`
- PowerShell: `-SkipCertificateCheck`

**План:** Переход на публичный сертификат запланирован к Production.

---

### Лимит запросов: 300/мин

Превышение лимита → HTTP 429.

Лимит общий на все запросы, независимо от модели.

---

### Отсутствие Production-мониторинга

В Beta-версии:
- Нет автоматических алертов при сбоях
- Нет дашбордов для пользователей
- Мониторинг осуществляется командой вручную

## Ограничения Beta

### Максимум 5 пользователей

Closed Beta ограничена 5 участниками. Расширение — после перехода к Production.

### Возможны сбои

Это Beta-версия. Возможны:
- Кратковременные перебои в доступности
- Изменения в API (с уведомлением)
- Непредвиденное поведение моделей

### Нет SLA

Время реакции на проблемы — best effort. Критические проблемы решаются в приоритетном порядке.
