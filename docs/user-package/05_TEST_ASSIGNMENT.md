## Задание 1: Получить список моделей

**Цель:** Проверить доступность API и корректность аутентификации.

Выполните запрос:

```bash
curl -k https://fb1.spb.ru:443/v1/models \
  -H "Authorization: Bearer ВАШ_API_КЛЮЧ"
```

**Ожидаемый результат:**
- HTTP 200
- В ответе две модели: `qwen-14b` и `qwen-32b-base`

**Отметьте:**
- [ ] Запрос выполнен успешно (HTTP 200)
- [ ] Обе модели присутствуют в ответе

## Задание 4: Типовые сценарии

**Цель:** Проверить систему на реалистичных задачах.

Выполните ВСЕ сценарии:

- [ ] **Сценарий A: Вопрос-ответ.** Задайте вопрос, получите ответ, задайте уточняющий вопрос.
- [ ] **Сценарий B: Несуществующая модель.** Запросите модель `"nonexistent-model"`. Ожидается HTTP 404.
- [ ] **Сценарий C: Неверный ключ.** Используйте `"Bearer bad-key-123"`. Ожидается HTTP 401.
- [ ] **Сценарий D: Без ключа.** Уберите заголовок Authorization. Ожидается HTTP 401.
- [ ] **Сценарий E: Неверный JSON.** Отправьте `{"bad": "json"}` — без `model`. Ожидается HTTP 422.

## Задание 5: Написать письмо

**Цель:** Проверить способность модели генерировать структурированный текст.

Запрос к `qwen-14b`:

> «Напиши официальное письмо клиенту о переносе сроков проекта на 2 недели. Укажи причину: дополнительные требования к тестированию. Тон: вежливый, профессиональный.»

**Ожидаемый результат:**
- Структурированное письмо
- Обращение, тело, заключение
- Профессиональный тон

**Отметьте:**
- [ ] Ответ структурирован
- [ ] Тон соответствует запросу
- [ ] Все ключевые пункты отражены

## Задание 7: Сделать резюме текста

**Цель:** Проверить способность суммаризации.

Возьмите текст из 3–5 абзацев (можно из новостей или документации) и попросите `qwen-14b`:

> «Сделай краткое резюме следующего текста (3–4 предложения): [ВАШ ТЕКСТ]»

**Ожидаемый результат:**
- Краткое резюме (3–4 предложения)
- Сохранены ключевые мысли
- Нет домысливания

**Отметьте:**
- [ ] Резюме действительно краткое
- [ ] Ключевые мысли сохранены
- [ ] Нет выдуманных фактов

## Задание 9: Работа с длинным текстом

**Цель:** Проверить обработку длинного контекста.

Отправьте сообщение длиной ~2000–3000 символов (например, статью или документацию) и попросите модель:

> «Ответь на вопросы по тексту выше: 1) О чём этот текст? 2) Какие ключевые выводы?»

**Ожидаемый результат:**
- Модель «понимает» контекст
- Ответы релевантны содержанию
- HTTP 200 (не 500/504)

**Отметьте:**
- [ ] Запрос обработан (не таймаут)
- [ ] Ответ соответствует содержанию
- [ ] Модель не «потеряла» контекст
