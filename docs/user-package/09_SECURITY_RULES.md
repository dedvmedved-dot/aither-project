## Учётная запись — ваша ответственность

Ваша учётная запись Web UI — это ваш основной доступ к системе:

- Привязана к вам лично
- Даёт доступ к чату, управлению ключами и статусу системы
- Позволяет идентифицировать ваши действия

**Вы несёте ответственность за все действия, выполненные под вашей учётной записью.**

---

## API-ключ — ваша ответственность

API-ключи (токены) — это доступ к API для программ и агентов:

- Создаются через Web UI (раздел 🔑 API Ключи)
- Префикс: `aither_`
- Можно иметь несколько ключей для разных целей
- Каждый ключ можно отозвать независимо

**Вы несёте ответственность за все действия, выполненные с вашими API-ключами.**

---

## Не передавайте учётные данные

❌ **Запрещено** передавать ваши учётные данные Web UI:
- Логин и пароль
- Токены сессии
- Cookies браузера

У каждого участника Closed Beta — **своя учётная запись**.

---

## Не публикуйте ключи

❌ **Запрещено** публиковать API-ключи:
- В GitHub (коммиты, issues, gists)
- В чатах (Telegram, Slack, Discord)
- На форумах
- В скриншотах
- В блогах и социальных сетях
- В коде, который попадает в открытый доступ

**Формат ключа:** `aither_...` — если вы видите такую строку в публичном месте, немедленно сообщите владельцу.

---

## Не используйте чужие ключи или учётные записи

❌ **Запрещено** использовать:
- API-ключ другого участника, даже с его разрешения
- Учётную запись другого участника

Каждый ключ и учётная запись:
- Отслеживаются отдельно
- Имеют свои лимиты
- Могут быть отозваны независимо

## Безопасность браузера

При использовании Web UI:

- ✅ **Выходите из системы** на общих компьютерах
- ✅ **Не сохраняйте пароль** в браузере на чужих устройствах
- ✅ **Закрывайте браузер** после завершения работы
- ✅ **Используйте приватный режим** (Incognito) на общих компьютерах
- ❌ **Не оставляйте открытую сессию** без присмотра

---

## Безопасность AI-агентов

При подключении AI-агентов через API-ключи:

- ✅ Создавайте **отдельный ключ** для каждого агента
- ✅ Используйте ключи **только для чтения моделей** (если поддерживается)
- ✅ Отзывайте ключи агентов, которые больше не используются
- ✅ Храните ключи в переменных окружения, а не в коде
- ❌ Не используйте личный ключ для агентов — создайте отдельный
- ❌ Не жёстко кодируйте (`hardcode`) ключи в исходном коде

Пример безопасного хранения:
```bash
export AITHER_API_KEY="aither_..."
```
```python
import os
key = os.environ["AITHER_API_KEY"]
```

## Конфиденциальность запросов

⚠️ **Внимание:** Aither находится в стадии Beta. Это означает:

- **Не передавайте конфиденциальные данные** через Web UI или API (пароли, персональные данные, коммерческую тайну)
- **Не загружайте чувствительные документы** (система не шифрует запросы на уровне приложения)
- **Система логирует запросы** для отладки и мониторинга

Используйте Aither для тестовых, неконфиденциальных задач.

## Сообщайте о подозрительной активности

Немедленно сообщите владельцу проекта, если:

- Не можете войти в Web UI без причины
- Ваш API-ключ перестал работать
- Вы получили ответ на запрос, который не делали
- Вы заметили необычную активность
- Кто-то попросил ваш пароль или ключ
- В списке ключей появились незнакомые

## Что делать при компрометации

### Компрометация пароля Web UI:
1. 🛑 Немедленно сообщите владельцу
2. 🔑 Запросите сброс пароля
3. ✅ Смените пароль при следующем входе

### Компрометация API-ключа:
1. 🛑 Немедленно **отзовите ключ** в Web UI (🔑 API Ключи → Отозвать)
2. 📞 Сообщите владельцу проекта
3. 🔑 Создайте новый ключ

**Время реакции на компрометацию: немедленно.**

## HTTPS и Test Zone

- **Internet:** `https://fb1.spb.ru:10443/` — HTTPS, доверенный сертификат Let's Encrypt
- **Test Zone:** `http://10.129.13.78:30080/` — HTTP, только внутренняя сеть
- При использовании API через Internet: флаг `-k` в curl **не требуется**
- При использовании Python: `verify=False` **не требуется**
- Test Zone использует HTTP — не передавайте конфиденциальные данные

## Не тестируйте безопасность

🚫 **Тестирование безопасности НЕ входит в задачи Closed Beta.**

Не пытайтесь:
- Сканировать порты
- Подбирать пароли или API-ключи
- Отправлять вредоносные запросы
- Искать уязвимости
- Обходить аутентификацию
- Пытаться получить доступ к чужим учётным записям

Это может быть воспринято как атака и привести к блокировке.

## API-ключи для агентов

**Рекомендации по созданию ключей для AI-агентов:**

| Тип использования | Рекомендация |
|---|---|
| Личное использование | 1 ключ на все задачи |
| AI-агент (автоматизация) | Отдельный ключ на каждого агента |
| Разработка и тестирование | Отдельный ключ |
| Продакшн-использование | Отдельный ключ, ротация при необходимости |

**Почему отдельные ключи?**
- Можно отозвать ключ агента, не затрагивая личный
- Лимиты отслеживаются раздельно
- При компрометации агента — ущерб изолирован

Подробнее: [AI AGENT CONNECTION PRIMER](16_AI_AGENT_CONNECTION_PRIMER.md).

Не используйте Aither для генерации:

- Вредоносного кода
- Спама
- Оскорбительного или дискриминационного контента
- Материалов, нарушающих законодательство

## Шпаргалка

| Ситуация | Действие |
|---|---|
| Забыл пароль Web UI | Запросить сброс у владельца |
| Потерял API-ключ | Отозвать и создать новый в Web UI |
| Опубликовал ключ | Немедленно отозвать, создать новый |
| Ключ перестал работать | Проверить статус в Web UI, сообщить владельцу |
| Подозрительная активность | Сообщить владельцу |
| Чужой ключ или учётная запись | Не использовать |
| Ключ для агента | Создать отдельный в Web UI |
