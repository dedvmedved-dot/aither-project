## Подготовка к запуску Beta

### Шаг 1: Проверьте инфраструктуру

Убедитесь, что система работает:

**Web UI:**
```bash
# Откройте в браузере
https://fb1.spb.ru:443/
```

**API:**
```bash
curl https://fb1.spb.ru:443/v1/models \
  -H "Authorization: Bearer ВАШ_API_КЛЮЧ"
```
Ожидается HTTP 200.

**Test Zone:**
```bash
curl http://10.129.13.78:30080/v1/models \
  -H "Authorization: Bearer ВАШ_API_КЛЮЧ"
```

## Управление API-ключами

Пользователи могут **самостоятельно** создавать и отзывать ключи через Web UI (раздел 🔑 API Ключи).

### Административное управление:

#### Создание ключа (Hermes):
```python
# Через ai-platform pod
kubectl exec -n aither-inference deploy/aither-ai-platform -- python3 -c "
import sqlite3, hashlib, secrets
raw_secret = secrets.token_urlsafe(48)
hex_part = secrets.token_hex(4)
full_key = f'athr_{hex_part}_{raw_secret}'
key_prefix = f'athr_{hex_part}'
key_hash = hashlib.sha256(full_key.encode()).hexdigest()
db = sqlite3.connect('/data/ai-platform.db')
db.execute('INSERT INTO api_keys (user_id, name, key_prefix, key_hash) VALUES (?,?,?,?)',
    (1, 'beta-user-XX', key_prefix, key_hash))
db.commit()
print(full_key)
"
```

#### Отзыв ключа:
```sql
UPDATE api_keys SET revoked_at = datetime('now') WHERE key_prefix = 'athr_XXXXXXXX';
```

#### Просмотр активных ключей:
```sql
SELECT key_prefix, name, created_at, last_used_at, revoked_at FROM api_keys WHERE revoked_at IS NULL;
```

#### Массовый отзыв (при завершении Beta):
```sql
UPDATE api_keys SET revoked_at = datetime('now') WHERE revoked_at IS NULL;
```

## Проведение Beta

### Во время Beta:

1. **Будьте на связи** с пользователями
2. **Отвечайте на вопросы** оперативно
3. **Собирайте Bug Report'ы** по мере поступления
4. **Мониторьте Web UI** — доступность и ошибки
5. **Не исправляйте ошибки «на лету»** без уведомления пользователей
6. **Ведите журнал инцидентов**

### Критерии остановки Beta (немедленно):

- Критическая уязвимость безопасности
- Утечка учётных данных или API-ключа
- Повторяющиеся 5xx, делающие систему непригодной
- Неработоспособность Web UI
- GPU-сбой без workaround
- >5 нерешённых критических дефектов

## Сбор обратной связи

### Что собирать:

- ✅ Bug Report'ы (форма `06_BUG_REPORT_TEMPLATE.md`)
- ✅ Feedback Forms (форма `07_USER_FEEDBACK_FORM.md`)
- ✅ Acceptance Checklists (форма `11_ACCEPTANCE_CHECKLIST.md`)

### Особое внимание при сборе:

- Удобство Web UI
- Скорость работы чата
- Понятность управления API-ключами
- Работа двух зон (Internet / Test Zone)

### Когда собирать:

- После выполнения пользователем всех тестовых заданий
- При обнаружении любой ошибки — сразу
- По окончании срока Beta

## Завершение Beta

### Когда завершать:

- Все пользователи выполнили задания
- Все Bug Report'ы собраны
- Все Feedback Forms получены
- Нет критических нерешённых проблем

### Шаги:

1. Соберите все отчёты от пользователей
2. Передайте результаты Hermes для анализа
3. Примите решение: Ready for Production / нужны доработки
4. При необходимости — отзовите все Beta-ключи (`UPDATE api_keys SET revoked_at = datetime('now')`)
5. При необходимости — деактивируйте учётные записи Web UI
6. Сообщите пользователям о завершении

## Аварийные ситуации

### Утечка учётных данных Web UI:
1. Немедленно смените пароль пользователя
2. Проверьте логи на предмет несанкционированного доступа
3. Попросите пользователя проверить созданные API-ключи

### Компрометация API-ключа:
1. Попросите пользователя отозвать ключ в Web UI
2. Или отзовите административно
3. Проверьте логи на предмет несанкционированного использования
4. Выдайте/создайте новый ключ

### Массовый сбой:
1. Сообщите пользователям о проблеме
2. Приостановите Beta
3. Выясните причину с Hermes
4. После исправления — возобновите Beta

### Web UI недоступен:
1. Проверьте статус сервера
2. Проверьте SSL-сертификат (Let's Encrypt, автообновление)
3. Сообщите пользователям, предложите API как временную альтернативу
4. После восстановления — уведомите пользователей

### Жалоба пользователя:
1. Зафиксируйте жалобу
2. Классифицируйте: баг / неудобство / предложение
3. Передайте Hermes для исправления (баги) или учтите в планах (предложения)
