## Назначение системы

Aither — это платформа для работы с большими языковыми моделями (LLM) через **Web UI** (основной способ) и OpenAI-совместимый API.

**Основные применения:**
- Диалоги и вопросно-ответные системы
- Генерация и продолжение текста
- Помощь в написании кода
- Перевод текста
- Создание резюме и аннотаций
- Подключение AI-агентов через API-токены

## Web UI — основной интерфейс

### Доступ

Откройте браузер и перейдите по адресу:
- **Internet:** `https://fb1.spb.ru:443/` (HTTPS, доверенный сертификат Let's Encrypt)
- **Test Zone:** `http://10.129.13.78:30080/` (HTTP, внутренняя сеть)

### Вход

Используйте **имя пользователя** и **пароль**, выданные администратором.

### Панель управления

После входа отображается:
- **Аккаунт:** имя пользователя и роль
- **Система:** версия и статус (Работает / Деградация)
- **Модели:** список доступных моделей
- **Зона:** Internet или Test Zone (автоопределение)
- **Быстрые действия:** чат, ключи, документация

### Основные разделы

| Раздел | Описание |
|---|---|
| 💬 **Чат** | Диалог с моделями в реальном времени |
| 🔑 **API Ключи** | Создание/просмотр/отзыв API-токенов |
| 📊 **Панель** | Статус системы и моделей |

## Чат с моделями через Web UI

### Выбор модели

В верхней части страницы — выпадающий список моделей:

| Модель | Тип | Описание |
|---|---|---|
| **qwen-14b** | Чат | Для диалогов, вопросов-ответов, инструкций |
| **qwen-32b-base** | Базовая | Для продолжения текста |

### Параметры

В интерфейсе можно настроить:
- **max_tokens** — максимальная длина ответа (по умолчанию: 2048)
- **temperature** — «креативность» ответа (0.0 = точно, 1.0+ = творчески)

### Отправка сообщения

1. Выберите модель
2. Введите сообщение
3. Нажмите **Enter** или ▶ Отправить
4. Дождитесь ответа (индикатор загрузки)

### Действия с ответом

- 📋 **Копировать** — копирует ответ модели
- **Очистить** — очищает историю диалога

## Управление API-ключами через Web UI

Перейдите в раздел **🔑 API Ключи**:

### Создание ключа

1. Нажмите **«+ Создать новый ключ»**
2. Введите название (например, «Мой проект»)
3. Выберите модели: обе / только 14B / только 32B
4. Нажмите **«Создать»**
5. ⚠️ **Скопируйте полный ключ!** Он показывается только один раз.

**Формат ключа:** `athr_...` (Bearer-токен)

### Отзыв ключа

1. Найдите ключ в таблице
2. Нажмите **«Отозвать»**
3. Подтвердите действие

Отозванный ключ немедленно перестаёт работать.

Подробнее: [API KEY USER GUIDE](14_API_KEY_USER_GUIDE.md).

## Неподдерживаемые сценарии

### ❌ Сценарий 1: Многошаговые диалоги с памятью через API
Система не сохраняет историю между запросами. Каждый API-запрос — новый.
**Обходной путь:** Передавайте историю в `messages` самостоятельно, либо используйте Web UI (история сохраняется в рамках сессии).

### ❌ Сценарий 2: Потоковая передача (streaming)
`stream: true` не поддерживается. Ответ приходит целиком.

### ❌ Сценарий 3: Вызов функций (function calling)
Модель не может вызывать внешние функции или API.

### ❌ Сценарий 4: Загрузка файлов
API не поддерживает загрузку файлов. Только текст.

### ❌ Сценарий 5: Тонкая настройка модели
Модели предоставляются «как есть». Тонкая настройка недоступна.

## Аутентификация

### Web UI
- Логин/пароль (выдаются администратором)
- Сессия сохраняется до выхода

### API
Каждый запрос должен содержать заголовок:
```
Authorization: Bearer ***
```

API-ключ создаётся в Web UI или выдаётся администратором.

**Формат ключа:** `athr_<префикс>_<секретная часть>`

**Без ключа** — `HTTP 401`.
**Неверный ключ** — `HTTP 401`.
**Просроченный/отозванный ключ** — `HTTP 401`.

Подробнее в [SECURITY RULES](09_SECURITY_RULES.md) и [API KEY USER GUIDE](14_API_KEY_USER_GUIDE.md).

## Формат запросов и ответов (API)

### Запрос (chat completions)
```json
{
  "model": "qwen-14b",
  "messages": [
    {"role": "user", "content": "Ваш вопрос"}
  ],
  "max_tokens": 200
}
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `model` | string | Да | ID модели (`qwen-14b` или `qwen-32b-base`) |
| `messages` | array | Да | Список сообщений. Каждое: `{"role": "user", "content": "..."}` |
| `max_tokens` | integer | Нет | Максимальное количество токенов в ответе (по умолчанию 2048) |
| `temperature` | float | Нет | «Креативность» (0.0–2.0, по умолчанию 0.7) |

### Ответ
```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "qwen-14b",
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": "Текст ответа модели"
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 30,
    "completion_tokens": 100,
    "total_tokens": 130
  }
}
```

## Рекомендации

1. **Используйте Web UI** для повседневной работы — это основной интерфейс.
2. **API** — для автоматизации и подключения AI-агентов.
3. **Для диалогов используйте qwen-14b** — она оптимизирована для общения.
4. **Для продолжения текста — qwen-32b-base** — более мощная, но базовая модель.
5. **Не делайте больше 4 одновременных API-запросов** к 14B — запросы встают в очередь.
6. **Делайте паузы между API-запросами** при интенсивном использовании.
7. **Проверяйте `finish_reason`** в ответе API: `"stop"` — успешно, `"length"` — ответ обрезан.
8. **Сохраняйте ID запроса** (`id` в ответе API) — пригодится для баг-репортов.
9. **Создавайте API-ключи в Web UI** — раздел 🔑 API Ключи.

## Коды ошибок

| Код | Описание | Что делать |
|---|---|---|
| 200 | Успех | Всё работает ✅ |
| 401 | Неверный или отсутствующий ключ/сессия | Проверьте ключ (формат: `athr_...`) или войдите заново |
| 404 | Модель не найдена | Проверьте `model` в запросе. Доступны: `qwen-14b`, `qwen-32b-base` |
| 422 | Неверный формат запроса | Проверьте JSON: обязательны `model` и `messages` |
| 429 | Слишком много запросов | Подождите минуту, лимит: 300/мин |
| 500 | Внутренняя ошибка сервера | Сообщите через [BUG REPORT](06_BUG_REPORT_TEMPLATE.md) |
| 504 | Таймаут шлюза | Модель не успела ответить. Повторите позже |
