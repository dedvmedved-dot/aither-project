## Доступ и аутентификация

### 1. Как получить API-ключ?
Обратитесь к владельцу проекта. Он выдаст вам персональный ключ формата `aither_XXXXXXXX_...`.

### 2. Что делать, если я потерял API-ключ?
Немедленно сообщите владельцу проекта. Старый ключ будет отозван, выдан новый.

### 3. Можно ли использовать один ключ на нескольких компьютерах?
Да, ваш персональный ключ можно использовать с любого устройства. Но не передавайте его другим людям.

### 4. Как проверить, что ключ работает?
Выполните `GET /v1/models`. HTTP 200 = ключ работает. HTTP 401 = ключ неверный.

### 5. Что делать при ошибке 401?
Проверьте:
- Правильно ли скопирован ключ (без лишних пробелов)
- Формат заголовка: `Authorization: Bearer ВАШ_КЛЮЧ`
- Не истёк ли ключ (сообщите владельцу)

## Модели

### 6. Какие модели доступны?
Две модели:
- `qwen-14b` — чат-модель, оптимизирована для диалогов
- `qwen-32b-base` — базовая модель, для продолжения текста

### 7. Какую модель выбрать?
- Для диалогов, вопросов-ответов, инструкций → `qwen-14b`
- Для продолжения текста, генерации → `qwen-32b-base`

### 8. Почему 32B отвечает «не по-человечески»?
`qwen-32b-base` — базовая модель, она не обучена вести диалог. Она просто продолжает текст. Для диалогов используйте `qwen-14b`.

### 9. Есть ли другие модели?
На данный момент — только эти две. Новые модели могут быть добавлены в будущих версиях.

### 10. Какой максимальный размер запроса?
Контекстное окно — 4096 токенов. Это примерно 3000–3500 слов на русском языке.

## Запросы и ответы

### 11. Как отправить запрос?
Самый простой способ — curl. См. [QUICK START](02_QUICK_START.md) и [API GUIDE](04_API_GUIDE.md).

### 12. Почему ответ обрезан?
Проверьте `finish_reason` в ответе:
- `"stop"` — модель завершила ответ
- `"length"` — ответ обрезан из-за ограничения `max_tokens`. Увеличьте `max_tokens`.

### 13. Можно ли вести многошаговый диалог?
Система не хранит историю. Чтобы продолжить диалог, передайте всю историю в массиве `messages`:
```json
{
  "messages": [
    {"role": "user", "content": "Привет"},
    {"role": "assistant", "content": "Здравствуйте!"},
    {"role": "user", "content": "Как дела?"}
  ]
}
```

### 14. Как получить ответ в JSON?
Просто попросите модель в запросе: «Ответь в формате JSON». Модель сама структурирует ответ.

### 15. Какой формат даты и времени использовать?
Модель понимает стандартные форматы: `2026-07-25`, `25 июля 2026`, `July 25, 2026`.

### 16. Поддерживается ли Markdown в ответах?
Да, модель может форматировать ответы с помощью Markdown: заголовки, списки, код.

## Ошибки

### 17. Что делать при HTTP 404?
Вы указали несуществующую модель. Доступны только `qwen-14b` и `qwen-32b-base`.

### 18. Что делать при HTTP 422?
Неверный формат запроса. Проверьте:
- JSON корректен?
- Поле `model` указано?
- `messages` — массив с элементами?

### 19. Что делать при HTTP 429?
Вы превысили лимит запросов (300/мин). Подождите минуту.

### 20. Что делать при HTTP 500 или 504?
Внутренняя ошибка или таймаут. Повторите запрос позже. Если повторяется — заполните [BUG REPORT](06_BUG_REPORT_TEMPLATE.md).

### 21. Что делать, если запрос «завис» и нет ответа?
Подождите до 60 секунд. Если за это время ответ не пришёл — модель перегружена. Повторите позже.

### 22. Почему ответ содержит «мусор» или бессмысленный текст?
Возможно для `qwen-32b-base` (нормально для базовой модели). Для `qwen-14b` — сообщите через Bug Report.

## Ограничения

### 23. Сколько запросов можно делать?
До 300 запросов в минуту, до ~4 одновременных на 14B.

### 24. Почему запросы идут медленно под нагрузкой?
14B использует GPU. При нескольких одновременных запросах они встают в очередь. Ожидание до 50 секунд при 4+ параллельных запросах — норма.

### 25. Сохраняются ли мои запросы?
Нет. Система не сохраняет историю диалогов. Каждый запрос независим.

### 26. Можно ли загружать файлы?
Нет. Только текст через API.

## Безопасность

### 27. Нужно ли использовать HTTPS?
Да, система работает только через HTTPS (порт 443). Сертификат самоподписанный — используйте флаг `-k` в curl.

### 28. Кто видит мои запросы?
Ваши запросы видны только вам и администраторам системы. Не передавайте конфиденциальные данные.

### 29. Что делать, если я случайно опубликовал API-ключ?
Немедленно сообщите владельцу проекта для отзыва ключа.

### 30. Можно ли тестировать безопасность системы?
Нет. Тестирование безопасности не входит в задачи Closed Beta.

## Общие вопросы

### 31. Сколько продлится Closed Beta?
По решению владельца проекта. Ориентировочно — несколько недель.

### 32. Будет ли система доступна после Beta?
Да, после успешного завершения Beta и Production Readiness система станет общедоступной внутри организации.

### 33. Могу ли я пригласить коллегу?
Нет. Состав участников определяется владельцем проекта. Максимум 5 человек.

### 34. Что делать, если я не могу выполнить задание?
Сообщите владельцу проекта. Это ценная информация — возможно, документацию нужно улучшить.

### 35. Как часто обновляется система?
По мере необходимости, с уведомлением участников. Критические обновления — немедленно.
