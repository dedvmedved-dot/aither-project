## Обзор

Aither предоставляет **две точки доступа** к системе. Функционально они идентичны, но различаются сетевым расположением и протоколом:

```
┌──────────────────────────────────────┐
│           Aither Platform            │
│                                      │
│  ┌─────────────┐  ┌──────────────┐   │
│  │  Internet    │  │  Test Zone   │   │
│  │  :443/HTTPS  │  │  :30080/HTTP │   │
│  └──────┬───────┘  └──────┬───────┘   │
│         │                 │           │
└─────────┼─────────────────┼───────────┘
          │                 │
    Интернет           Внутренняя
    (открытый)       сеть / VPN
```

**API-ключи и учётные записи — общие.** Один логин/пароль и один API-ключ работают в обеих зонах.

## Зона Internet

### URL

```
https://fb1.spb.ru:443/
```

### Характеристики

| Параметр | Значение |
|---|---|
| **Доступ** | Открытый (из любой точки интернета) |
| **Протокол** | HTTPS |
| **Сертификат** | Let's Encrypt (доверенный) |
| **Порт** | 443 |
| **Бейдж в UI** | 🌐 INTERNET (зелёный) |

### Когда использовать

- ✅ Основная повседневная работа
- ✅ Доступ из дома, офиса, командировки
- ✅ Любое устройство с интернетом
- ✅ Работа с конфиденциальными данными (HTTPS шифрует трафик)

### API-доступ

```bash
# Internet (API)
curl https://fb1.spb.ru:443/v1/models \
  -H "Authorization: Bearer athr_..."
```

## Зона Test Zone

### URL

```
http://10.129.13.78:30080/
```

### Характеристики

| Параметр | Значение |
|---|---|
| **Доступ** | Внутренняя сеть / VPN |
| **Протокол** | HTTP |
| **Сертификат** | Отсутствует (HTTP) |
| **Порт** | 30080 |
| **Бейдж в UI** | 🧪 TEST ZONE (жёлтый) |

### Когда использовать

- ✅ Доступ из внутренней сети организации
- ✅ Тестирование из изолированной среды
- ✅ Когда Internet-доступ недоступен (брандмауэры, CGNAT)
- ✅ Быстрая проверка без HTTPS-накладных расходов

### API-доступ

```bash
# Test Zone (API)
curl http://10.129.13.78:30080/v1/models \
  -H "Authorization: Bearer athr_..."
```

## Сравнение зон

| Характеристика | Internet | Test Zone |
|---|---|---|
| **URL** | `https://fb1.spb.ru:443/` | `http://10.129.13.78:30080/` |
| **Доступ** | 🌐 Открытый (интернет) | 🔒 Внутренняя сеть / VPN |
| **Протокол** | HTTPS | HTTP |
| **Шифрование** | ✅ TLS (Let's Encrypt) | ❌ Нет |
| **Сертификат** | Доверенный (автоматический) | Нет |
| **Бейдж** | 🌐 INTERNET (зелёный) | 🧪 TEST ZONE (жёлтый) |
| **API Base URL** | `https://fb1.spb.ru:443` | `http://10.129.13.78:30080` |
| **curl флаги** | Не требуются | Не требуются |
| **Функционал** | Полный | Полный |
| **Учётная запись** | Общая | Общая |
| **API-ключи** | Общие | Общие |

## Как определить зону?

Web UI автоматически определяет зону по URL, через который вы вошли:

| URL входа | Бейдж |
|---|---|
| `https://fb1.spb.ru:443/` | 🌐 **INTERNET** |
| `http://10.129.13.78:30080/` | 🧪 **TEST ZONE** |

Бейдж отображается:
- На панели управления
- В верхней части страницы

## API-доступ в разных зонах

Один и тот же API-ключ работает в обеих зонах. Различается только базовый URL:

### Internet

```python
import requests

BASE = "https://fb1.spb.ru:443"
KEY = "athr_..."

r = requests.get(f"{BASE}/v1/models",
    headers={"Authorization": f"Bearer {KEY}"})
```

### Test Zone

```python
import requests

BASE = "http://10.129.13.78:30080"
KEY = "athr_..."

r = requests.get(f"{BASE}/v1/models",
    headers={"Authorization": f"Bearer {KEY}"})
```

> 💡 **Совет:** Храните базовый URL в конфигурации/переменной окружения:
> ```bash
> export AITHER_BASE_URL="https://fb1.spb.ru:443"  # или http://10.129.13.78:30080
> ```

## Когда какую зону использовать?

### Internet — для повседневной работы

```
Сценарий: Вы работаете из дома или офиса, есть доступ в интернет.
Действие: Откройте https://fb1.spb.ru:443/ — это основная точка входа.
```

### Test Zone — для специальных случаев

```
Сценарий 1: Вы находитесь в изолированной сети без доступа в интернет.
Действие: Используйте http://10.129.13.78:30080/ через внутреннюю сеть.

Сценарий 2: Вам нужно протестировать систему изнутри инфраструктуры.
Действие: Подключитесь к VPN, откройте Test Zone.

Сценарий 3: Internet-зона временно недоступна.
Действие: Переключитесь на Test Zone как резервный канал (если есть доступ).
```

## Ограничения

### Test Zone — без шифрования

Test Zone использует HTTP. Данные передаются открытым текстом в пределах сети.

**Последствия:**
- Не используйте Test Zone для конфиденциальных запросов
- Трафик может быть перехвачен внутри сети (маловероятно, но теоретически возможно)
- Для повседневной работы предпочтительнее Internet (HTTPS)

### Test Zone — требуется доступ к сети

Test Zone недоступна из интернета. Нужно либо:
- Находиться в офисе (внутренняя сеть)
- Подключиться через VPN

### Общие лимиты

Лимит запросов (300/мин) — общий на обе зоны. Запросы из Internet и Test Zone суммируются.

## Часто задаваемые вопросы

### Нужно ли создавать отдельный ключ для Test Zone?
Нет. API-ключи работают в обеих зонах. Один ключ — два URL.

### Нужна ли отдельная учётная запись для Test Zone?
Нет. Используйте те же логин и пароль.

### Почему Test Zone на HTTP, а не HTTPS?
Test Zone предназначена для внутреннего использования. HTTPS требует доменного имени и сертификата, что избыточно для IP-адреса во внутренней сети.

### Что делать, если Test Zone недоступна?
Проверьте:
1. Вы подключены к внутренней сети или VPN?
2. IP-адрес `10.129.13.78` доступен? (`ping 10.129.13.78`)
3. Порт 30080 открыт? (`curl http://10.129.13.78:30080/`)

Если всё равно недоступна — используйте Internet-зону или сообщите администратору.

### Можно ли использовать обе зоны одновременно?
Да. Можно открыть Internet в одном браузере, Test Zone — в другом. Сессии независимы.

### Какую зону использовать для AI-агента?
Зависит от того, где работает агент:
- Агент в интернете → `https://fb1.spb.ru:443`
- Агент во внутренней сети → `http://10.129.13.78:30080`

API-ключ один и тот же.
